FAIL high AF-WIN-ACCT-006 Minimum local password length meets current NIST guidance (>=15 characters)
Observed
0
Expected
>= 15
Why
NIST SP 800-63B-4 Sec. 3.1.1.1-3.1.1.2 (verified by direct PDF read, see docs/SOURCES.md) SHALL requires verifiers to enforce a minimum of 15 characters for passwords used as a single authentication factor (8 characters minimum is only acceptable when the password is one factor of MFA), SHOULD support at least 64 characters, and explicitly SHALL NOT impose composition/complexity rules beyond a compromised-password blocklist check. This supersedes the older, widely-cited "8-14 chars plus complexity" guidance -- see section 3 of the project spec ("do not blindly implement old hardening advice") and AF-WIN-ACCT-007's notes.
Reference
NIST SP 800-63B-4 — https://csrc.nist.gov/pubs/sp/800/63/b/4/final
Remediation
Available
Possible Impact
Users with shorter existing passwords must change them at next reset, not immediately.
FAIL high AF-WIN-AUTH-002 LAN Manager authentication level restricts legacy LM/NTLMv1
Observed
3
Expected
>= 5
Why
LM and NTLMv1 use weak, crackable challenge/response schemes. Requiring NTLMv2-only (and refusing the legacy variants) removes an easy downgrade target, while stopping short of Microsoft's broader in-progress NTLM deprecation roadmap (see docs/SOURCES.md), which is not yet default-on for currently supported releases and is out of scope for this control.
Reference
Microsoft Security Baseline — https://learn.microsoft.com/en-us/windows-server/security/kerberos/preventing-pth-attacks
Remediation
Available
Possible Impact
Breaks authentication to very old (pre-Windows 2000/legacy SMB/NAS) systems that only understand LM or NTLMv1.
